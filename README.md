# Teresio Gassino — GitHub Pages Site

A static tribute site with real content, bilingual Italian/English text set in Merriweather, and scroll/load-triggered image animations. No build tools required.

## Structure
```
site/
├── index.html                      ← landing page
├── home.html                       ← full essay
├── logos.html
├── discorso.html
├── curriculum.html
├── galleria.html                   ← Foto
├── quercia.html                    ← hidden page, NOT in nav, linked from home.html text only (also the one page with no .page-subtitle — see "Deliberate choices" below)
├── en/                              ← English counterpart of every page above, same filenames (see "English version" below)
├── css/style.css
├── js/animations.js
├── DECISIONS.md                    ← the long-form reasoning behind the CSS (see "Reading the CSS" below)
├── fonts/                          ← self-hosted Merriweather/Merriweather Sans .woff2 files (see "Font" below)
├── pdf/                            ← source PDFs linked from Discorso, Curriculum and Logos 27 (patents, scanned documents)
├── sfondi/                         ← decorative/UI SVGs and favicons (flags, ornamental dividers, spinner, favicon)

```

Each Italian page has an English counterpart at the same filename under `/en/` (see "English version" below).

## Reading the CSS
`css/style.css` carries one short comment per rule saying **what that rule does now**. Anything longer than that — measurements taken, approaches tried and reverted, bugs reproduced on a real phone, browser quirks identified by name — lives in `DECISIONS.md`, and the stylesheet points at it by number: `→ DECISIONS.md §37`. The two are meant to be read together; the split exists because ~60% of the stylesheet used to be comment, and most of that was history rather than description, which is not what you want to read past when you open the file to change a colour.

**Adding a rule that needs more than a line of explanation**: put the line in the stylesheet, the reasoning in `DECISIONS.md`, and number it after the last entry. Don't renumber existing entries — every number is referenced from the stylesheet. Retire an entry by marking it obsolete rather than deleting it.

`js/animations.js` is the exception: its comments stay inline and are long on purpose. They explain non-obvious control flow (why a class is added on `animationend` rather than on `:hover`, why a `<dialog>`'s native focus trap still needs a Tab handler), which is worth having in front of you while reading the code it describes.

## Font
Merriweather (serif) and Merriweather Sans are self-hosted in `fonts/` (`.woff2`, SIL Open Font License — see `fonts/OFL-merriweather.txt`), loaded via `@font-face` in `css/style.css`. No Google Fonts request is ever made — nothing to load from a third-party server, no IP shared with Google. The files were sourced from the Fontsource npm packages (`@fontsource/merriweather`, `@fontsource/merriweather-sans`), which redistribute Google Fonts for exactly this purpose.

Weights included: Merriweather 300/400/700/900 + 400 italic, Merriweather Sans 300/400/700/800 + 400 italic. Merriweather 300 (serif light) is declared but unused — harmless to leave, safe to drop; Sans 300 *is* used, by `.essay-subtitle`. The five sans page titles (Index, Logos 27, Discorso, Curriculum, Foto) use Sans 800; the family has no 900 cut, so don't set `font-weight: 900` on them.

## 1. Images
All content photos are served as WebP, sized close to their actual display context (roughly 2× the CSS display width, for retina screens) rather than at whatever resolution the source scan or camera happened to produce — a card thumbnail shown at 180px isn't served a 2000px-wide file. Two of the Curriculum scans, the CFM diploma and the Cavaliere honour diploma, are each served twice: once as an on-page WebP thumbnail (800px wide), and once as a larger WebP (`-full` suffix, up to 1600px on the long edge) opened via the document viewer rather than a separate image link. `curriculum-fronte.webp` is linked only once, at 1200px, with no larger version. `images/creative.png` (the footer's Creative Commons badge) and every SVG in `sfondi/` are untouched — already small enough that neither conversion nor resizing would meaningfully help.

Six images do double duty as `og:image`/`twitter:image` social-preview sources as well as on-page thumbnails (`card-tecnigrafo`, `logos-pintori`, `curriculum-fronte`, `discorso/capellaro`, `teresio-tecnigrafo`, `galleria/foto-01`) — each is sized to at least 1200px on the long edge, above the usual social-platform minimum, even where the on-page thumbnail itself would need less. Quercia's own `og:image` (`quercia/quercia-1-clump.webp`) is the exception: it's served at its on-page clump-thumbnail size (630×415), below that same minimum, since that page has no larger on-page version of the photo to reuse.

No image uses `loading="lazy"`, deliberately: every image already fades/slides in via its own IntersectionObserver reveal, which already defers visual appearance until it's in view. Stacking native lazy-loading on top risks desyncing the animation from when the image's bytes actually arrive.

## 2. Layout notes

- **Header**: a fixed, translucent gray nav bar (`rgba(220,220,220,0.68)`, same opacity as the footer, with a blur), content constrained to a centered `.nav-inner` (max-width 900px) so the brand and links don't stick to the viewport edges on wide screens. "Teresio Gassino" links to the landing page. It hides on scroll down and reappears on scroll up. **On mobile** (below `67.5em` — 1080px at a default 16px font, see "Typography" below for why this one is in em), the links collapse into a burger menu on the right; tapping it animates open and the burger morphs into an X — tap again (or tap a link, or tap outside) to close. The bar stays visible while the dropdown is open. The closed dropdown is `visibility: hidden`, not merely collapsed to `max-height: 0` — that keeps it out of the tab order and the accessibility tree, which the collapse alone never did. Hovering a nav link shows an underline but does **not** bold it: bolding a `nowrap` item in a `space-between` row widens it and shoves its siblings sideways. Only `.active` carries weight, and it is set in the markup and never changes while the page is open.
- **Typography**: every `font-size` in the stylesheet is in `rem`, resolved against `html { font-size: 100% }` — i.e. against the reader's own browser setting, not a number of ours. (The common `62.5%` trick is deliberately *not* used: it would quietly override a larger default back down.) Structural sizes — padding, radii, borders, layout breakpoints — stay in px; type scales, boxes don't have to. Three things had to scale with the type or raising the default font would have broken the layout instead of helping: `body`'s `padding-top` and `main`'s `padding-bottom` (the space reserved under the fixed nav and above the fixed footer), `.brand-signature`'s height, and the nav breakpoint, which is in `em` because what it measures is how much room six text labels need. Full reasoning in `DECISIONS.md` §B. There is no `clamp()` in the file yet: several remaining breakpoints exist only to step a font size down by hand and would collapse into one — a worthwhile follow-up, not done.
- **Typefaces**: Merriweather (serif) for body text; Merriweather Sans for the nav, the footer, and every small "Fonte: ..." citation line (class `.fonte`) — gives those UI/metadata bits their own visual register instead of sharing the reading typeface. The five section-index pages (Index, Logos 27, Discorso, Curriculum, Foto) use a sans-serif `<h1>` instead, echoing the nav bar's own typeface; Home and Quercia keep the serif title. Each of those five titles is followed by a `.page-subtitle` in the *opposite* register (serif italic), for contrast against the sans title above it.
- **Footer**: fixed gray bar, all text black, Creative Commons logo first followed by the credit line. **On a landscape phone it stops being fixed** and scrolls away with the page — a fixed nav plus a fixed footer were taking about a quarter of a ~390px-tall viewport, and it's a credit line, not navigation. `main`'s bottom padding, which exists only to clear a fixed footer, drops accordingly. See `DECISIONS.md` §D.
- **Translucent chrome**: the nav, the footer, the language pill, the burger dropdown and `.ritagli-band` are all translucent over the page rather than opaque, and depend on `backdrop-filter` to stay legible. Every one of them declares `-webkit-backdrop-filter` as well — Safari before 18 knows only that spelling — and an `@supports not (...)` block gives browsers with neither an opaque equivalent tuned to the same apparent colour. `.ritagli-band` gets a solid `#4C4C4C` there rather than a higher white alpha, because it is a *dark* panel carrying light text and more white would wash it out. See `DECISIONS.md` §E.
- **Side-by-side image + description** (Logos 27, Curriculum): any `<figure class="reveal-img side">` shows the image and its `<figcaption>` next to each other (stacks on mobile). Add `from-right` to flip which side the image is on, and `align-top` to align the text to the top of the image instead of centering it vertically. `crop-top` (crop the image from the top instead of the center) is a plain `.reveal-img` modifier, not exclusive to this side-by-side pairing — it's also used on its own in the Foto grid.
- **Image badges** (Logos 27, Curriculum): every linked image gets a small pill badge in the bottom corner (PDF / Link / Enlarge) via `.img-badge`, plus a subtle darkening overlay on hover, so it's clear upfront that the image is clickable and what it opens. `.img-badge` and `.clump-badge` are both 12px — deliberately not 11px, which is where they started; below 12px a label is recognised by shape rather than read, and `.clump-badge` carries an instruction, not a one-word category.
- **Clump animation** (Un discorso di Capellaro, Quercia): the thumbnails in `.clump-stage` slide in and land clustered, on page load — pure CSS. Discorso uses six photos at 370×240px each, entering from different sides, with all the page's text sitting below in a single dark translucent `.ritagli-band`. Quercia reuses the same mechanism for just two photos at 630×415px, above its own (shorter) `.ritagli-band` intro paragraph: both enter from the right, staggered via their own `animation-duration`/`--delay` inline, so the left-bound one lands first and the right-bound one just after — see `DECISIONS.md` §40 for why they share a launch side. Below 800px the clump switches to a plain vertical stack at readable size instead of the clustered layout. That threshold is 800px and not 640px for a concrete reason: the clustered layout is built from fixed pixel offsets (Discorso's pair spans 756px, Quercia's 712px) and neither shrinks with the viewport, so between 641px and roughly 760px the outer edge of each column used to be cut off — and because `body` carries `overflow-x: hidden`, the overflow wasn't even scrollable. See `DECISIONS.md` §36.
- **Document viewer** (Discorso's two Banchelli photos, Curriculum's diploma/onorificenza photos, both Quercia photos): a second native `<dialog>` (`.doc-viewer-overlay`, distinct from the Foto lightbox below), opened via any `.doc-viewer-trigger` — enlarges the image and, where a transcript exists, shows a "Versione testuale" pill button (`.doc-viewer-toggle`) that swaps the image for the transcribed text, cloned in from a `<template>` on open (`initDocViewer()` in `js/animations.js`). Quercia replaced its earlier fixed-height scroll-window treatment with this same pattern, for consistency with Discorso. While the (often large) full-resolution scan loads, the image is held at `opacity: 0` behind a spinner; **both** `onload` and `onerror` clear that state, so a file that never arrives shows the browser's broken-image placeholder and its `alt` text rather than a spinner that turns forever. Where a transcript exists the "Versione testuale" button still works in that case — it clones from an inline `<template>` and doesn't depend on the image at all.
- **Per-image reveal** (Home, Logos 27, Curriculum, Foto, Quercia): each image fades/slides in individually as it scrolls into view, via `observeReveal(selector)` in `js/animations.js` — one parameterised `IntersectionObserver` called twice, once for `.reveal-img` (slide in from a side) and once for `.essay-anim` (rise and fade, Home only). Each call builds its own observer over its own element set; the two classes stay separate on purpose, because `.essay-anim` is applied per element and deliberately skips the title, epigraph and closing source note that a blanket `.reveal-img` would catch. Which animation plays is a property of the selector, not of the function. Every content image also carries `width`/`height` attributes matching its real file dimensions, so the browser can reserve the right space before the file loads (avoids layout shift) — paired everywhere with an explicit `height: auto` in CSS, since the two together are what actually let the browser compute a *proportional* height instead of using the attributes' raw pixel values verbatim.
- **Foto grid hover**: once a thumbnail's entrance reveal finishes, `initGalleryReveal()` adds `.settled`, handing control from the entrance `animation` to a plain `transition` — from there, hovering (`hover: hover` and `pointer: fine` devices only) scales the image to 1.5× within its own card (`overflow: hidden` on `.reveal-img` crops it to the card's bounds) and fades in a caption gradient (`.gallery-caption`) with the photo's `data-caption` text. The caption also appears on `:focus-within`, so a keyboard user tabbing to a thumbnail sees what hovering it would have shown; and under `@media (hover: none)` it is simply always on, because on touch these six captions were previously unreachable except by opening each photo in the lightbox. The same `:focus-within` pairing is applied to the clump badges and to the photo-darkening on the coloured cards. See `DECISIONS.md` §54 for why `from-right` photos need a duplicate selector.
- **Lightbox**: a native `<dialog>` (see "Accessibility & SEO" below), opened via any `.lightbox-trigger` button — each one wraps an `<img>` and carries a `data-caption` for the text shown under the enlarged photo. Used on the Foto grid and the two standalone photos on Home.

## 3. What happens when something breaks
The site has no build step and no third-party dependencies, so there is not much to go wrong — but what can go wrong does so quietly, and each case is guarded.

- **If `js/animations.js` fails, the content still shows.** The reveal animations start from `opacity: 0`, and that starting state is gated behind a `.js` class that the inline `<head>` script adds. On its own that arrangement fails badly: a 404 after a bad deploy, a parse error, or an exception in any one `init*()` would leave every paragraph of the Home essay and every image on Logos 27 / Curriculum / Foto invisible, permanently. So `animations.js` sets `window.__animsReady = true` as the **last** statement of its `DOMContentLoaded` handler — not the first line of the file, because the question isn't "did this file arrive" but "did every observer actually get attached" — and the inline script checks that flag on `load`, swapping `.js` back to `.no-js` if it's missing. Degraded outcome: no animations, everything on screen. If you add an `init*()` call, add it *above* that flag.
- **If a document scan fails to load**, the viewer stops pretending to load it — see "Document viewer" above.
- **Back-navigation.** `history.scrollRestoration` is forced to `manual` on a fresh navigation but left at `auto` when `performance.getEntriesByType('navigation')[0].type` is `back_forward`, so the browser restores your reading position when you come back from a link. This matters because internal links no longer open in new tabs (see "Deliberate choices"): without it, following a reference out of the middle of the Home essay and pressing Back dropped you at the top of it.

## 4. Accessibility & SEO
- Every page has a self-referencing `<link rel="canonical">` alongside its existing `hreflang` alternates — the two homepages (`index.html` and `en/index.html`) canonicalize to their clean root URLs (`https://teresioweb.github.io/`, `.../en/`) rather than the `/index.html` form, since both resolve to the same page on GitHub Pages and only one should be the one search engines index.
- The lightbox and the document viewer are both real `<dialog>` elements opened with `.showModal()`, not styled `<div>`s — focus trapping, Escape-to-close, and top-layer stacking all come from the browser rather than hand-rolled JS. A small supplementary Tab handler patches one Chromium quirk on each (focus briefly passing through `document.body` at the wrap points instead of cycling directly between controls); everything else about the trap is native. Lightbox and document-viewer triggers are real `<button>`/`<a>` elements, so focus and Enter/Space activation are native too.
- **Colour-coded ritagli, made screen-reader-accessible.** The six photographed excerpts on "Un discorso di Capellaro" each carry a `.visually-hidden` transcription (clip technique, not `display:none` — stays in the accessibility tree), so screen-reader users get the same text a sighted user gets from the scanned image. Since the colour-coding that ties each photo to its source paragraph below (see "Deliberate choices") is otherwise a purely visual cue, each hidden transcription opens by naming its own colour and which numbered paragraph ("first", "second"...) it points to, rather than assuming the reader can see the link.
  **The transcription is a sibling of the `<a>`, not a child of it** — this matters and is easy to undo by accident. Inside the link it became part of the link's *accessible name*: a screen reader announced each control as its `alt` text, plus the badge, plus 150-odd words of transcript, all as one name, which made those entries unusable in a rotor/links list. As a sibling it is still read in place immediately after the link, still invisible on screen, and no longer names anything.
- **Heading structure.** Logos 27 and Curriculum each present four separate documents, and until recently had an `<h1>` and nothing else — navigating by heading returned the page title and stopped. On Logos 27 the line already doing a title's job (the document's name and what it is) is now a real `<h2>` with `font: inherit`, which undoes h2's own defaults so it renders exactly as it did as a bold run at the head of a paragraph. Curriculum has no such line — its bold runs sit mid-sentence — so each of its four figures carries a `<h2 class="visually-hidden">` naming the document instead. Foto was left alone deliberately: six headings for six photos is noise, and turning the grid into a `<ul>` needs `display: contents` on the `<li>`, which has a history of stripping the list role in exactly the assistive technology the change would be for. See `DECISIONS.md` §A.
- **Real lists.** The four articles on Logos 27 and the seven patents on Curriculum used to be single `<p>`s held together by `&gt;` characters and `<br>` line breaks — announced as one long paragraph full of greater-than signs rather than "list, 7 items". Both are `<ul class="doc-list">` now, with the `>` marker redrawn as a `::before` so they render identically: no bullet, no indent, no gap between items.
- Decorative elements (the burger icon's bars, empty `alt=""` on purely ornamental images) are excluded from the accessibility tree.
- `robots.txt` points to `sitemap.xml`, which lists all 14 pages (7 Italian + 7 English) with their `hreflang` relationships.

## 5. English version (`/en/`)
The site is bilingual: every Italian page has an English counterpart at the same filename under `/en/` — `curriculum.html` ↔ `en/curriculum.html`, and so on (same rule for all 7 pages, including the hidden `quercia.html`).

- **Shared assets, one copy.** The English pages don't duplicate CSS, JS, fonts, or images — they reference the exact same files as the Italian ones do, via **absolute paths from the domain root** (`/css/style.css`, `/js/animations.js`, `/images/...`, `/sfondi/...`, `/pdf/...`). This is why they work correctly one directory level deep without needing `../`. The Italian pages use relative paths (`css/style.css` etc.) instead.
- **`hreflang` tags.** Every page's `<head>` (both languages) has `<link rel="alternate" hreflang="...">` tags pointing to its counterpart, so search engines treat the two as translations of the same page rather than duplicate content.
- **Canonical link targets.** Nothing links to `index.html` in its `/index.html` form — the brand link on every page and the language switcher on the two homepages point at the clean root URLs (`./` from an Italian page, `/en/` and `/` for the switcher), matching what those pages declare as their own `<link rel="canonical">`. Both resolve to the same document on GitHub Pages, and internal links pointing at the non-canonical spelling of a page is a signal worth not sending.
- **Language switcher**: a small pill floats just right of the nav bar on desktop (`.lang-link-desktop`, position: fixed, deliberately outside `.nav-inner` so it never competes for space in the bar). Its `left` is derived from the bar's own geometry — `calc(50% + min(475px, 50vw) + 12px)`, which is exactly where a 950px-wide centred bar ends, plus a 12px gap — rather than tuned by eye against `vw`, which used to drift further from the bar the wider the window got. Below the nav breakpoint it hides and the same link appears instead as the last item in the burger dropdown (`.lang-link`), flag icon plus label. Both are plain links to the sibling page in the other language — no JavaScript involved, no state to keep in sync.
- **Two flag icons** live in `sfondi/`: `flag-it.svg` and `flag-gb.svg`, small hand-drawn SVGs (not emoji, for consistent rendering across every OS/browser).
- **Extra footnote in the English essay.** `en/home.html` includes an additional footnote, (**), giving international readers background on Natale Capellaro that Italian readers are assumed to already have — it doesn't exist in the Italian version, by design.
- **Translation approach for proper names and titles**: book, article, and chapter titles are kept in their original language (they're real citations, not paraphrased) with an English gloss added in quotes — e.g. *Il sogno di un'impresa* ("The dream of an enterprise"). This applies throughout Logos 27, Curriculum, and "A speech by Capellaro".

## 6. Deliberate choices
A few things that look like inconsistencies or omissions on a quick pass, kept as-is on purpose:

- **Colour as meaning, only where it already has a referent.** The highlighted quotes on "Un discorso di Capellaro" link in colour to the specific excerpt they're citing — that's colour carrying real meaning. Extending the same colour-coding logic site-wide (tying section or page colours to some recurring meaning across the whole site) was considered and dropped: without a concrete referent behind it, the same device reads as a gimmick, and it would force meaning onto colour choices that are just visual rhythm everywhere else on the site.
- **Internal links stay in the same tab.** `target="_blank"` is for external sites and for the PDFs and full-resolution scans only. It used to be on the in-essay references to Logos 27, Discorso and Quercia as well, which meant a reader following three references out of the Home essay ended up with four tabs of the same site and a Back button that did nothing. Those are plain links now, paired with the `scrollRestoration` handling described in "What happens when something breaks".
- **No `.page-subtitle` on Quercia**, unlike the other five section pages. It's a one-paragraph easter-egg page; matching Home's sans-serif subtitle treatment here would be more formatting than the content can carry.

## 8. Turn on GitHub Pages
Settings → Pages → Source: "Deploy from a branch" → Branch: `main`, folder `/ (root)` → Save. Since the repo is named `teresioweb.github.io` (a user/organization site), it deploys straight to `https://teresioweb.github.io/` — no repo name in the path. Live within a minute or two.

## 9. Known, and not addressed
Kept here so nobody has to rediscover them. These are open items, not "deliberate choices" — the difference matters.

- **The four ritagli colours are doing too much work.** On "Un discorso di Capellaro" the tie between a highlighted word and the excerpt it cites is carried by colour alone, which is a WCAG 1.4.1 concern since the colour is meaning here and not decoration. Measured: yellow (`#FEE8B2`) and peach (`#FFDDC2`) are ΔE ≈ 14 apart in normal vision, pink and peach ≈ 18 — already marginal for a code whose members are never adjacent — and under simulated deuteranopia/protanopia the three warm tints collapse onto each other. The fix doesn't need a redesign: putting the author's name in each clump badge ("Capellaro", "Piol", "Sartor", "Banchelli") adds a second channel and is the information a reader wants anyway, leaving colour as reinforcement.
- **The decorative background SVGs are the heaviest thing on most pages.** `sgimignano.svg` is 157 KB gzipped for an illustration sitting under an 0.85 dark overlay — roughly half of Quercia's whole image payload, for something rendered at ~15% visibility. `vite.svg` is 38 KB gzipped for an ornament a few dozen pixels wide (8,117 numbers in a single traced `<path>`). SVGO at reduced precision helps; rasterising the ones that render small helps more.
- **The fonts are not subset.** They are already Latin-only (231 glyphs) but the whole site, both languages, uses 109 characters. Subsetting to those cuts the serif faces ~60% — about 320 KB → 130 KB across all ten cuts. Only worth doing with a `subset.sh` in the repo, since it has to be re-run whenever the copy gains a character.
- **`loading="lazy"` is still off everywhere** — see "Images" for the stated reason. Worth re-testing: native lazy-loading starts fetching well before an element enters the viewport, while the reveal observer fires at 20% visible, so the two probably don't collide the way the note assumes.
- **No JSON-LD** on Logos 27, Foto, Curriculum or Quercia, and no Wikidata URI (`Q103831208`) in the `sameAs` of the `Person` schema.
- **No Content-Security-Policy.** GitHub Pages can't send headers, but a `<meta http-equiv>` would work: the single inline script is byte-identical across all 14 pages, so a hash-based policy needs exactly one hash. Recompute it after any edit to that script.
- **Foto's grid is not a list** — see "Heading structure" for why that was left alone rather than forced.
